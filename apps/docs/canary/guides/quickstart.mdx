This guide creates a minimal Rigkit project that prepares a Freestyle VM,
caches a snapshot, and creates named workspaces from that snapshot.

## Install Rigkit

```sh
curl -fsSL https://www.rigkit.dev/install | sh
```

Open a new terminal so your shell can find `rig`, then check the install:

```sh
rig version
```

## Create a project

```sh
mkdir website
cd website
pnpm add -D @rigkit/sdk @rigkit/provider-freestyle @rigkit/provider-cmux freestyle
rig init
```

`rig init` creates:

- `rigkit/index.ts`, the workflow config.

It does not prompt and does not write package metadata, environment files, or
ignore rules.

## Understand the generated config

The generated `rigkit/index.ts` prepares a Node.js 22 Freestyle VM, installs
GitHub CLI, opens a browser-backed `gh auth login` terminal when needed, clones
`octocat/Hello-World`, and snapshots the result.

The workspace lifecycle hook uses that snapshot to create a long-lived
workspace VM. The generated workspace operations are `ssh`, `open-cmux`, and
`open-vscode`.

## Plan and apply

Run a plan first:

```sh
rig plan
```

The plan shows which tasks are already cached and which tasks are pending.
On the first run, the setup task is pending.

Apply the workflow:

```sh
rig apply
```

During apply, Rigkit starts the project runtime, loads `.env`, creates provider
runtimes, runs pending tasks, and writes cached task outputs to
`.rigkit/state.sqlite`.

Run the plan again:

```sh
rig plan
```

Now the setup task should be cached. Rigkit can reuse the snapshot until the
task code, provider config, upstream task output, output schema, cache TTL, or
manual invalidation makes it stale.

## Create and list workspaces

Create a workspace from the prepared workflow context:

```sh
rig create dev
```

List workspaces:

```sh
rig ls
```

Remove the workspace when you are done:

```sh
rig rm dev
```

## Run an operation

Apply the config, create a workspace if you do not already have one, then run:

```sh
rig run dev ssh
rig run dev open-cmux
rig run dev open-vscode
```

## Common next steps

- Change the generated repository setup to clone your repo and install dependencies.
- Return `devPort`, branch names, and other JSON values in workflow context.
- Add workspace operations such as `status`, `test`, or `preview`.
- Move expensive shared setup into a global fragment when multiple repos use
  the same base image.
