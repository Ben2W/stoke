This guide creates a minimal Rigkit project that prepares a Freestyle VM,
caches a snapshot, and creates named workspaces from that snapshot.

## Install Rigkit

```sh
curl -fsSL https://www.rigkit.dev/install | sh
```

Open a new terminal so your shell can find `rig`, then check the install:

```sh
rig version
```

## Create a project

```sh
rig init website --package-manager pnpm
cd website
```

`rig init` creates:

- `rigkit/index.ts`, the workflow config.
- `package.json`, with local `@rigkit/sdk` and provider dependencies.
- `.env` and `.env.example` when you pass `--api-key`.
- `.gitignore`, including `.env` and `.rigkit/`.

If you skip dependency installation during init, install them before running
the project:

```sh
pnpm install
```

## Understand the generated config

The generated `rigkit/index.ts` has three important parts:

```ts
import { workflow } from "@rigkit/sdk";
import { freestyle, VmBaseImage, VmSpec } from "@rigkit/provider-freestyle";

const vmSpec = new VmSpec()
  .baseImage(new VmBaseImage("FROM node:22"))
  .idleTimeoutSeconds(3600);

export const dev = workflow("dev", {
  providers: {
    freestyle: freestyle.provider(),
  },
}).sequence("website")
  .step("verify-node-22", async ({ providers }) => {
    const { vm, vmId } = await providers.freestyle.client.vms.create({
      spec: vmSpec,
      logger: console.log,
    });

    try {
      const result = await vm.exec("node --version");
      if (!result.stdout.trim().startsWith("v22.")) {
        throw new Error(`Expected Node.js v22, got: ${result.stdout}`);
      }
      const snapshot = await vm.snapshot();
      return { ctx: { snapshotId: snapshot.snapshotId } };
    } finally {
      await providers.freestyle.client.vms.delete({ vmId });
    }
  })
  .workspace({
    create: async ({ workflow, providers }) => {
      const { vmId } = await providers.freestyle.client.vms.create({
        snapshotId: workflow.ctx.snapshotId,
        logger: console.log,
      });
      return { vmId };
    },
    remove: async ({ providers, workspace }) => {
      await providers.freestyle.client.vms.delete({ vmId: workspace.ctx.vmId });
    },
  });
```

The workflow step creates a VM, verifies it has Node.js 22, snapshots it, and
returns `snapshotId` in the workflow context. The workspace lifecycle hook uses
that snapshot to create a long-lived workspace VM.

## Plan and apply

Run a plan first:

```sh
rig plan
```

The plan shows which tasks are already cached and which tasks are pending.
On the first run, the setup task is pending.

Apply the workflow:

```sh
rig apply
```

During apply, Rigkit starts the project runtime, loads `.env`, creates provider
runtimes, runs pending tasks, and writes cached task outputs to
`.rigkit/state.sqlite`.

Run the plan again:

```sh
rig plan
```

Now the setup task should be cached. Rigkit can reuse the snapshot until the
task code, provider config, upstream task output, output schema, cache TTL, or
manual invalidation makes it stale.

## Create and list workspaces

Create a workspace from the prepared workflow context:

```sh
rig create dev
```

List workspaces:

```sh
rig ls
```

Remove the workspace when you are done:

```sh
rig rm dev
```

## Add your first operation

Workspaces become useful when the config exposes operations. Add a terminal
provider and an `ssh` operation:

```ts
import { workflow } from "@rigkit/sdk";
import { freestyle, VmBaseImage, VmSpec } from "@rigkit/provider-freestyle";

export const dev = workflow("dev", {
  providers: {
    freestyle: freestyle.provider(),
    terminal: freestyle.terminal(),
  },
}).sequence("website")
  // existing setup task
  .workspace({
    create: async ({ workflow, providers }) => {
      const { vmId } = await providers.freestyle.client.vms.create({
        snapshotId: workflow.ctx.snapshotId,
        logger: console.log,
      });
      return { vmId };
    },
    remove: async ({ providers, workspace }) => {
      await providers.freestyle.client.vms.delete({ vmId: workspace.ctx.vmId });
    },
  })
  .workspaceOperation("ssh", {
    title: "SSH",
    description: "Open a shell in the workspace VM",
    run: async ({ providers, workspace }) => {
      await providers.terminal.open(`SSH ${workspace.name}`, {
        ssh: await providers.freestyle.createSSHOptions({
          vmId: workspace.ctx.vmId,
        }),
        keepOpenAfterCommand: true,
      });
    },
  });
```

Apply the config, create a workspace if you do not already have one, then run:

```sh
rig run dev ssh
```

## Common next steps

- Add repository setup steps that clone your repo and install dependencies.
- Return `repoPath`, `devPort`, and other JSON values in workflow context.
- Add workspace operations such as `open-cmux`, `open-vscode`, `ssh`, `status`,
  or `preview`.
- Move expensive shared setup into a global fragment when multiple repos use
  the same base image.
