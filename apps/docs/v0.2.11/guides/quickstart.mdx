This guide creates a minimal Rigkit project, prepares it once, and creates one
workspace.

## Install

```sh
curl -fsSL https://www.rigkit.dev/install | sh
```

Open a new terminal, then verify the CLI:

```sh
rig version
```

## Initialize a project

```sh
rig init
cd website
```

<Note>
Agents, CI, and other non-interactive callers should avoid prompts and parse
JSON:

```sh
rig init website --package-manager skip --json
cd website
pnpm install
```

Use `--json` on later commands, and use `--yes` when removing workspaces.

</Note>

`rig init` creates:

- `rigkit/index.ts`
- `package.json` with local `@rigkit/sdk` and provider dependencies
- `.gitignore` entries for `.env` and `.rigkit/`
- `.env` and `.env.example` only when `--api-key` is passed

The generated config uses Freestyle browser login by default:

```ts
const freestyleProvider = freestyle.provider();
```

If you want API-key auth, change that line to:

```ts
import { env } from "@rigkit/sdk";

const freestyleProvider = freestyle.provider({
  apiKey: env.secret("FREESTYLE_API_KEY"),
});
```

## What was generated

The starter config prepares a Node.js 22 Freestyle VM and snapshots it:

```ts
export const dev = workflow("dev", {
  providers: {
    freestyle: freestyleProvider,
  },
}).sequence("website").step(
  "verify-node-22",
  async ({ providers }) => {
    const { vm, vmId } = await providers.freestyle.client.vms.create({
      spec: vmSpec,
      logger: console.log,
    });

    try {
      const result = await vm.exec("node --version");
      if (
        (result.statusCode ?? 0) !== 0 ||
        !result.stdout.trim().startsWith("v22.")
      ) {
        throw new Error(
          `Expected Node.js v22, got: ${result.stdout}${result.stderr}`,
        );
      }

      const snapshot = await vm.snapshot();
      return { ctx: { snapshotId: snapshot.snapshotId } };
    } finally {
      await providers.freestyle.client.vms.delete({ vmId });
    }
  },
);
```

It also defines how to create and remove workspace VMs from that snapshot:

```ts
.workspace({
  create: async ({ workflow, providers }) => {
    const { vmId } = await providers.freestyle.client.vms.create({
      snapshotId: workflow.ctx.snapshotId,
      idleTimeoutSeconds: vmIdleTimeoutSeconds,
      logger: console.log,
    });
    return { vmId };
  },
  remove: async ({ providers, workspace }) => {
    await providers.freestyle.client.vms.delete({ vmId: workspace.ctx.vmId });
  },
})
```

The only persisted values here are `snapshotId` and `vmId`.

## Plan and apply

```sh
rig plan --workflow dev
rig apply --workflow dev
rig plan --workflow dev
```

The first plan shows the setup task as pending. `rig apply` runs it and stores
the task output in `.rigkit/state.sqlite`. The second plan should show the task
as cached.

Cached setup is reused until a cache input changes: task code, provider config,
upstream task output, output schema, `cacheTTL`, provider artifact validation,
or manual invalidation.

## Create a workspace

```sh
rig create --workflow dev dev
rig ls
```

`rig create` runs `apply` first if setup is stale, then calls
`workspace.create`. Remove the workspace when you are done:

```sh
rig rm dev
```

## Add an SSH operation

Workspaces are useful once the config exposes operations. Add the terminal
provider and a workspace operation:

```ts
export const dev = workflow("dev", {
  providers: {
    freestyle: freestyleProvider,
    terminal: freestyle.terminal(),
  },
}).sequence("website")
  // keep the generated setup task and workspace lifecycle
  .workspaceOperation("ssh", {
    title: "SSH",
    description: "Open a shell in the workspace VM",
    run: async ({ providers, workspace }) => {
      await providers.terminal.open(`SSH ${workspace.name}`, {
        ssh: await providers.freestyle.createSSHOptions({
          vmId: workspace.ctx.vmId,
        }),
        keepOpenAfterCommand: true,
      });
    },
  });
```

Run it:

```sh
rig apply --workflow dev
rig create --workflow dev dev
rig run dev ssh
```
