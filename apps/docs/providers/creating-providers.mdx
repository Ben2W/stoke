<Note>
This page is for users building a **new provider package** (e.g., a custom
integration for an internal database service or platform). Most users —
including most config authors — never need to write a provider. If you're just
wiring built-in providers into a config, see the
[provider overview](/providers/overview).
</Note>

Create a provider when workflow code needs a stable integration boundary around
an external system: an internal platform, a database service, a cloud API, a
local tool, or a host capability.

A provider has three pieces:

- a provider definition returned from `defineProvider(...)`;
- a provider plugin with `createProvider(...)`;
- a controller that creates the runtime used by tasks and operations.

## Minimal provider shape

```ts
import {
  defineProvider,
  type WorkflowProviderDefinition,
} from "@rigkit/sdk";
import type {
  BaseProviderPlugin,
  ProviderStorage,
  WorkflowProviderController,
} from "@rigkit/engine";

const ACME_DB_PROVIDER_ID = "acme-db";

type AcmeDbConfig = {
  apiUrl: string;
  token?: string;
};

type AcmeDbBranchRef = {
  provider: typeof ACME_DB_PROVIDER_ID;
  kind: "branch";
  branchId: string;
  url: string;
};

type AcmeDbRuntime = {
  createBranch(input: { name: string }): Promise<AcmeDbBranchRef>;
  deleteBranch(input: { branchId: string }): Promise<void>;
};

export type AcmeDbProviderDefinition = WorkflowProviderDefinition<
  typeof ACME_DB_PROVIDER_ID,
  AcmeDbConfig,
  AcmeDbRuntime
>;

export function acmeDbProvider(
  config: AcmeDbProviderDefinition["config"],
): AcmeDbProviderDefinition {
  return defineProvider(ACME_DB_PROVIDER_ID, config, acmeDbProviderPlugin);
}

const acmeDbProviderPlugin: BaseProviderPlugin = {
  providerId: ACME_DB_PROVIDER_ID,
  async createProvider({ provider, storage }) {
    const config = parseConfig(provider.config);
    return createAcmeDbController(config, storage);
  },
};
```

The config passed to `defineProvider(...)` may contain plain values or resolver
functions such as `env.secret("ACME_DB_TOKEN")`. Rigkit resolves provider config
before `createProvider(...)` receives it.

## Implement the controller

The controller owns the provider id, creates a runtime for each node, and can
validate cached artifacts.

```ts
function createAcmeDbController(
  config: AcmeDbConfig,
  storage: ProviderStorage,
): WorkflowProviderController<AcmeDbRuntime> {
  return {
    providerId: ACME_DB_PROVIDER_ID,

    runtime(context) {
      return {
        createBranch: async ({ name }) => {
          const branch = await createBranchInAcme(config, name);
          const ref: AcmeDbBranchRef = {
            provider: ACME_DB_PROVIDER_ID,
            kind: "branch",
            branchId: branch.id,
            url: branch.url,
          };

          storage.set(`branch:${ref.branchId}`, ref);
          context.metadata({ branchId: ref.branchId });
          return ref;
        },

        deleteBranch: async ({ branchId }) => {
          await deleteBranchInAcme(config, branchId);
          storage.delete(`branch:${branchId}`);
        },
      };
    },

    validateArtifact(ref) {
      return isBranchRef(ref) && Boolean(storage.get(`branch:${ref.branchId}`));
    },
  };
}
```

Rigkit scans task output for objects shaped like `{ provider: string, kind:
string }`. Those objects are treated as provider artifacts. When a cached run
contains artifacts, Rigkit asks the matching provider to validate them if the
provider implements `validateArtifact(...)`.

## Use the provider

```ts
import { env, workflow } from "@rigkit/sdk";
import { acmeDbProvider } from "@acme/rigkit-provider-db";

const app = workflow("api", {
  providers: {
    db: acmeDbProvider({
      apiUrl: "https://db.internal.example.com",
      token: env.secret("ACME_DB_TOKEN"),
    }),
  },
});

export default app
  .sequence("api")
  .task("create-db-branch", async ({ db }) => {
    const branch = await db.createBranch({ name: "rigkit-api" });
    return {
      ctx: {
        database: branch,
      },
    };
  })
  .workspace({
    create: async ({ workflow }) => ({
      databaseUrl: workflow.ctx.database.url,
    }),
    remove: async () => {},
  });
```

The task output stores the branch ref, not a live client object.

## Parse and validate config

Provider config is user input. Validate it before creating the controller.

```ts
function parseConfig(value: unknown): AcmeDbConfig {
  if (!value || typeof value !== "object" || Array.isArray(value)) {
    throw new Error("acme-db provider config must be an object");
  }

  const record = value as Record<string, unknown>;
  if (typeof record.apiUrl !== "string" || record.apiUrl.trim() === "") {
    throw new Error("acme-db provider config requires apiUrl");
  }
  if (record.token !== undefined && typeof record.token !== "string") {
    throw new Error("acme-db provider token must be a string");
  }

  return {
    apiUrl: record.apiUrl,
    token: record.token,
  };
}
```

For package providers, prefer a schema library so errors are consistent and
easy to read.

## Use provider storage

`createProvider(...)` receives two storage handles:

- `storage`: project/provider storage for JSON records tied to the selected
  project.
- `hostStorage`: host/provider storage for developer-machine credentials or
  login state.

Both stores support:

```ts
storage.get("key");
storage.set("key", { ok: true });
storage.delete("key");
storage.entries("prefix:");
```

Use task context for workflow outputs the user should see and compose. Use
provider storage for provider implementation details.

## Use host capabilities

Provider runtimes receive a `local` host boundary through the runtime context.
Use it for actions that must happen on the developer's machine.

```ts
runtime(context) {
  return {
    openDashboard: async (url: string) => {
      await context.local.open(url);
    },
    runTrustedCommand: async () => {
      const result = await context.local.command?.({
        argv: ["acme", "status"],
        mode: "capture",
        reason: "Check local Acme CLI authentication",
      });
      return result?.stdout;
    },
  };
}
```

For richer host integrations, define a named host capability and have a trusted
host register a handler. The cmux provider uses this pattern for `cmux.open`.

## Present provider-owned interactions

Providers can ask the host to present a URL and wait for completion. Freestyle
terminal sessions use this path.

```ts
runtime(context) {
  return {
    login: async () => {
      await context.interaction.present({
        title: "Log in to Acme",
        url: "https://acme.example.com/device",
        instructions: "Complete the browser login, then return to Rigkit.",
        completed: waitForLogin(),
        stop: async () => {
          await cancelLogin();
        },
      });
    },
  };
}
```

The provider owns the interaction URL and completion promise. The host owns how
that interaction is shown to the user.

## Provider design guidelines

- Keep provider config JSON-serializable and validate it at startup.
- Put durable resource refs in task context.
- Put implementation details in provider storage.
- Put developer-machine credentials in host storage.
- Implement `validateArtifact(...)` for cached refs whose remote resource may
  disappear.
- Use `context.metadata(...)` for run metadata that helps debug provider work.
- Use `context.local` only for explicit host actions.
- Keep runtime methods high-level enough that project configs stay readable.

## Complete helper functions

The example above uses these placeholders:

```ts
async function createBranchInAcme(
  config: AcmeDbConfig,
  name: string,
): Promise<{ id: string; url: string }> {
  const response = await fetch(`${config.apiUrl}/branches`, {
    method: "POST",
    headers: {
      "content-type": "application/json",
      ...(config.token ? { authorization: `Bearer ${config.token}` } : {}),
    },
    body: JSON.stringify({ name }),
  });

  if (!response.ok) {
    throw new Error(`Acme branch create failed: ${response.status}`);
  }

  const data = await response.json() as { id: string; url: string };
  return data;
}

async function deleteBranchInAcme(
  config: AcmeDbConfig,
  branchId: string,
): Promise<void> {
  await fetch(`${config.apiUrl}/branches/${branchId}`, {
    method: "DELETE",
    headers: config.token
      ? { authorization: `Bearer ${config.token}` }
      : {},
  });
}

function isBranchRef(value: unknown): value is AcmeDbBranchRef {
  return Boolean(
    value &&
      typeof value === "object" &&
      (value as Record<string, unknown>).provider === ACME_DB_PROVIDER_ID &&
      (value as Record<string, unknown>).kind === "branch" &&
      typeof (value as Record<string, unknown>).branchId === "string" &&
      typeof (value as Record<string, unknown>).url === "string",
  );
}
```
